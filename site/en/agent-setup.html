Connect any compatible MCP agent

Configure the following capabilities in your agent's MCP settings. These are connection requirements, not a universal JSON configuration schema. Direct MCP does not require Python.

CapabilityRequirement
TransportRemote Streamable HTTP over HTTPS
EndpointPrivately supplied service base URL plus /mcp
AuthenticationAuthorization bearer header from MUMU_API_KEY through the agent's secret mechanism
ProtocolNegotiate a version the deployed server supports
InvocationDiscover tools; follow their advertised JSON argument schemas
  1. Apply these capabilities using your product's settings and the session key from Connect. The resulting settings must contain a secret reference and the private endpoint. Do not paste a key into configuration text.
  2. Restart the agent from the shell where you entered the key. The agent must report an authenticated MCP connection. If it offers only OAuth or stdio, this direct path is unsupported; use the CLI if shell tools are available. If neither path is available, contact your administrator privately.
  3. Use the agent's tool discovery. The result must include recommend_patterns, get_pattern, get_related_patterns, check_composition and get_intake_form, with argument schemas. If any is absent, stop and contact your administrator privately.
  4. Ask the agent to call recommend_patterns for your own generic problem using the discovered schema. Require a successful authenticated result before using the recommendations. Do not save the response in public logs. If negotiation fails, report it privately; do not infer compatibility from the latest MCP specification.

Historical independent discovery and an authenticated call negotiated protocol 2025-11-25. This does not attest the current deployment or its full supported-version set; other versions remain unverified. A product's MCP label alone proves none of these capabilities. Browser clients also need compatible server origin/CORS policy; browser support is unverified.

Product examples and measured interoperability

Codex CLI: place the template below in ~/.codex/config.toml, replace only the URL with your private full endpoint, and restart from the same shell. The bearer environment setting is documented in official Codex MCP documentation.

[mcp_servers.mumu]
url = "https://mumu.example.invalid/mcp"
bearer_token_env_var = "MUMU_API_KEY"

Claude Code: use the JSON below as .mcp.json in a private, untracked recipient workspace, replace only the URL, and restart. Keep type: http and the environment reference. See official Claude Code MCP documentation. Do not run header-adding commands containing the key.

{
  "mcpServers": {
    "mumu": {
      "type": "http",
      "url": "https://mumu.example.invalid/mcp",
      "headers": {
        "Authorization": "Bearer ${MUMU_API_KEY}"
      }
    }
  }
}

Historical macOS checks of Codex CLI 0.167.1 and Claude Code 2.1.322 used their actual MCP hosts for five-tool discovery and explicit authenticated tool calls, with zero model invocations. Evidence applies to unchanged canonical configuration inputs; it does not attest current installed agent versions, model-driven behavior or every interactive mode. See coverage and limitations.
